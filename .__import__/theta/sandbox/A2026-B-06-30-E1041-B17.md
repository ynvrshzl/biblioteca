## 2.0 - "Ontonological edge"

From local experience; there is a real ontological edge, at which poorly-implemented code becomes more effort than investing upfront into proper implementation. Viewed from this lens, the engineering of code is twofold:

- Cognitive economics: how engineering becomes an interface for structural coherence, as byproduct, human readability.

- System performance: how engineering solves problems at performance level.

However, Minecraft is an incredibly complex game; and it's source code (de-compiled java and official source) reveals the phenomenological aspect of engineering; product first, coherence last.

From local experience, as stated previously; systems that prioritize product over coherence, are volatile to scaling. A poorly implemented script is fine for human working memory (7 (+/-) 2 ). But a poorly implemented game lifecycle? That's not just 50 little poorly implemented scripts; what results is a combinatorial explosion of complexity.... it behaves more like 50 little scripts that combine in "x" unknown paths... resulting in a system that becomes increasingly difficult to develop... almost like a building with outdated engineering...

That's how I could describe the most complex code... it appears that when we try to impose structure, the code naturally becomes slow... like a perfectly sanitized, sterile surgical room...

...but as we increase expressive power of code... we also see a building go from "clean, hyper organized, everything is known" to "this works but I don't know why or how long it'll last..."

That's the first phenomenon we should focus on in this research; software as physical engineering, in virtual space; specifically the phenomenological (almost physical, structural) effects of coding large-scale systems.

Given this, I am curious; are engineering and software just two distant worlds? Have people explored the proper application of engineering principles in software? Or is software, by design, almost always bound to the natural complexity of human expressiveness? Is it the expressiveness of code that acts as both it's most fundamental power, and it's cognitive volatility?
