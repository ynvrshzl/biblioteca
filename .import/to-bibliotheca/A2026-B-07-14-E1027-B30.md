One very interesting, and deeply concerning observation I have, about modern technology and software, is that... there very much are "invariant principles"... a set of fundamental computational laws, like that of the laws of physics... but software is not those laws... it appears to be an expressive interface, for implementation and prototyping... and I think becuase software is the only engineering of it's kind (it's virtual, and unlike chemical engineering or electrical engineering, there exists little to no instruments to study the structural composition and makeup of virtual systems, the way there are for the afformentioned fields of engineering.)... modern technology exists as a strange implementation experiment, that somehow passed the test for "good enough!"

I envision something like defining the invariant principles first, and then implementing a proper construction interface, from the princples, not above the princples (important distinction... becuase we shouldn't hide source, we should transform how we work with it and process it.)

I envision something like this:

- Today there are 50+ implementation models for writing a user preferences settings system.

- In the near future, we may need to define the invariant mechanics (e.g., storage layer, transformation, schema, device-persistence, security, etc.) and allow languages to implement systems, extending from core attributes and parts.

This is a distinction from

- A framework which provides modular microarchitecture

- And a set of code grammar for modular architecture

We may see some day, a "meta" language.
