this is fascinating, if software engineering, at source General systems level, is not sufficient for reasoning about real world problems, or building sophisticated architectures, how do engineers individually solve this problem? it's strange because it seems that software engineering requires us to implement our own constraints, our own grammar... which is strange ontologically, because...

a function could be classified as an ontological unit of information; a function encodes "this will happen when executed."

but...

"function api(x, a { args })" becomes a unit of epistemology; "how do I define what will happen when executed?" then the ontology no longer becomes about execution function, it becomes a new kind of information object... "what is API doing?" the moment we create a function, the program has shifted ontological, epistemlogical, cognitive baseline... from "I can use a function to execute this code" to "how do I structure these ideas?" 

at the moment of conception, from the Baseline General programming language, to author defined systems, we essentially engineer our own language interface. we don't think of it as designing our own grammar, but I believe this is what is happening ontologically! 

what's even more fascinating, is what happens when we can no longer reason about the system at the level of prototyping "how can this code execute an expected result?" once code complexity increases, a phenomenon emerges; "how can I model this set of relationships so that we understand that the system as it scales?"

and that's essentially the main area of friction that our recent Studies have focused on. essentially the polarity between 
- Ontology (programming as a set of rules, engineering as the cartography of problem solving)
- prototype, implementation (the bare minimum version of a functional program)
- system, engineering (principles of architecture, information organization, and constraint, as applied to virtual information space)
- output, product (what the code is producing. graphical, behavioral, life cycle, etc.)
- ontological, epistemological structure of code (how the source is structured, and how we human beings phenomenologically experience it as cognitive mass)
- ontological, epistemological structure of output (what is this system providing for the human being, outside of the source code?)

no longer reason about the subsurface strata of baseline execution what are the limits of the model? how much can we encode into one thing? what can we handle cognitively? is this the most effective, scalable implementation?
