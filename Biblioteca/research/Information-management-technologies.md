We are developing a "research/problem-solving" methodology field of study, in which the central thesis is designed to assist the Human being in solving real-world complex problems, by equipping oneself with the knowledge necessary to make decisions in real-time (this may arguably, be the purpose of knowledge and theory...)

In order to avoid getting lost in Theory; Let's develop this alongside a real-world problem that is deeply relevant today; "information transportation and communication in a busy cyberspace; comparing sample technologies HTML and MarkDown."


Apart from the Affordances & Necessities of an Editor, if we compared the Objective and Phenomenological fields between HTML and MarkDown, I argue we HTML would be a more sustainable technology, especially considering the fact that MarkDown was originally intended to simplify HTML as an Editorial grammar set... and most technologies today are using the Web, especially in the PKM, Editorial Research scene.

I wonder why use MarkDown in any case whatsoever, especially considering it's divergent "flavors", non-standardized spec, and it's browser dependency; which is perhaps the most imprtant field of comparison; because, regardless of editor, implementation or flavor, the end output is eventually going to be read. The focus in this case then, is not the processor, but the output:

a -> b -> c

Where "a" is the information, knowledge or material the Human Being is processing and working through. "b" is the processor, the technology, the computer. "c" is the output. This is as essential, abstract and close to the metal as we can get (so it is Axiomatic in some sense...)

This is the fascinating part; the relata, is not merely a forward-facing one-shot, it is a Cybernetic lifecycle:

c -> a -> b -> c -> a -> b, ...

The output information is read by the author whom authored the original material. So the Editor, the File Format, and even the grammar for each technology, is essentially high-level noise. If we abstract the problem, it is elegant and powerful, but it leaves gaps in assumption.

I think a defensible, actionable, observable Hypothesis is something like..."What format makes sense today, tomorrow, and 5 years ago?"

That last field is unexpectedly important; a future-facing format will implode epistemic assumptions that are too costly in local term; while seeking backward, is paradoxically, searching for the invariants; the timeless artifacts. What has already been explored, and tried, tested and affirmed. If we had instead formulated our Hypothesis by "5 years in the future" we would be looking in the opposite direction of Essentialism; Proceduralism

This resembles a radar chart of sparsed categories of comparison, rather than arbitrary database fields of comparison. We begin by mapping out each format and it's eventual Human-interaction (important)

e.g., "Which format serves purposes for x, y or z?"

Apart from the Editor enviornment... What are genuine necessities or affordances for choosing HTML over MarkDown, or any other portable file format, for that matter? What even is the underlying abstract problem of file formats? Do we use file formats, merely by necessity, choice or deliberate design? This is a fascinating set of problems, though it is mostly centralized into the Phenomenological, Authoring aspect... becuase in some fundamental sense, all file formats can eventually be converted from one form to another (Transmogrification) and are designed to be exported and integrated into other platforms (Transportability) and the Enviornment dictates how the content is rendered and how it is authored... which in some sense is captured in McLuhan's brilliant quote:

"The message is the medium."

This suggests a fascinating abstraction:

$$a \rightarrow (x) \rightarrow c$$

$$b = x(a)$$

Where "a" is the input information, "c" is the output, and "x" is the processor (the transformation from "a" to "c"). This is also a Cybernetic lifecycle, in essence, since "c" depends on "a", from the Editorial, Authoring perspective. And from the Viewers, Reader perspective, "c" is the first thing one sees, as a Composition space... but eventually, "a" needs to be re-editable in order for information to update, transform, change and evolve across time (very important for all Systems.)

I think the underlying abstract problem is something like... "Regardless of File format, Editor or Associated Toolchains, the end product is always some form of readable, accessible representation of information."

This points the problem into a much more cohesive form; "Editorial Affordances and Representations"

HTML + The Web, even if offline, affords a vast enviornment of technologies. While formats such as MarkDown, are designed to be light-weight and readable as-is; without an Editor. However, if we inspect the General Purpose of the format; it's formatting (hyperlinks especially) is arguably the core Function, which presents real-world tools for the Human being to connect and construct systems of information.
