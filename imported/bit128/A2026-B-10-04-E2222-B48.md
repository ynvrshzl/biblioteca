[6] "Where CDE Breaks."

Following our example of Redstone, Minecraft's Redstone arsenal is immensely powerful, precisely due to it's physically-modelled-constraints (PMC). Where are examples of CDE breaking? Arguably, it is up to the Architectural-schemata of the builder to manage the System and avoid Entropy-Overload (^O/e!)

Command blocks introduce a virtualized Domain of instruction; which introduces nonlinear, hyperdimensional functionality. Essentially, the player is not only an editor of the construction; but of the very constraints themselves. A command block can essentially control any part of the game (it is essentially a highly constrained Java interpreter machine, so it inherits "code-like" functionality.) Thiis presents a unique Continuum problem; Constraint vs. Control. A redstone repeater can only exhibit a specific set of behavior within a range of a circuit; but a command can exhibit virtually any behavior, within any given range.

This is where software, and alike examples emerge. Infact, it is what inspired "Constraint Theory"
