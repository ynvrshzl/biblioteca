Naming in Computation, reveals it's Linguistic Topology.

We assign a name to binary. That name is not arbitrary. We assign a rule to it's structure; that rule is not arbitrary. There are only a finite set of rules that can optimize the non-finite space; that is the basis of "Alpha Invariance."

A fascinating part of modern virtual Software is the Engineering aspect. We aren't taught this in CS; but much of software engineering is secretly Creativity + Knowledge + Topology + Linguistics + Logic + Problem-solving. Those five (non-exhaustive) domains largely form the manifold archtiecture of Software-Engineering.

And this tends to really matter in an increasingly hyperconnected world; we hold a responsibility for the Ethics and Governance of these systems; and it begins not at the level of Political Dichotomy; but at the tired Engineer working though a complex Labyrynth of wires and data flow, mostly invisible to perception. Yet behind the scrolls of code, the Engineer is building an internal Map of the Labyrynth; an Atlas.

Here's what's fascinating about this; The lingusitic aspect of code is increasingly visible from the Evolutionary Abstraction of C -> to Browser -> to JS -> to React (etc.) We see this common trend in almost all Domains of Cyber-Engineering aswell; from C to Game engines, or even Firmware to C. At each stage, not only is "power" arbitrarily increasing; but a specific variant of power; Expression and Control.

Linguistics offers both; and here's the original observation; everything from the Iota-scales of Binary, to the Graphical Interfaces; are all Abstractions where we project a stable source of meaning on a stable underlying form. This does not mean "meaning is arbitrary" quite the contrary; "meaning is a commitment about the function beneath a form"... atelast in Engineering contexts. What something "means" is essentially, it's purpose, function or role. It's "effect" in a Causal chain.

Code is essentially massive Causal-chains, authored by Human beings.

Commitment naturally forms a contract; a binding of structure; a Topology. Commitment without Communication, is essentially Form without Meaning;

The relata of Function and Form is especially important to understand in the Engineering world; becuase much of Technology is Abstracted behind Interfaces, Infrastructures, Systems and "Functions." Ideally, we do not interact with the underlying implementation of Systems; especially in Cognitively demanding Software systems. Here's a little quote to capture this idea: "The job of an Engineer is to build a shell as beautiful as it's internal wiring. A reflection of function, captured in form."

Infact, the "Function" is an integral part of code. Without it; there is no control over execution order (a compiler would process code in the order it is written in. with a function, especially function hoisting; a program can execute in non-linear form; that's the basis of modern technology becuase it establishes flow control.) The Function is the smallest unit of code that can contain within it, a procedure (or sub-program, or sub-routine) of re-use. In other words, the function establishes control of execution and sequence; much like that of a Symphony.

But here's the primary obsevation; everything in code has either a symbol or name. Those symbols or names were authored by engineers.
