# The problem with source code
How come patterns aren't standardized? Not "programming patterns", but patterns as a language?

e.g.,

"Micro state machine": This micro-model machine processor, is the software equivalent of a multiplexer + condition checker. When state and condition is required, when if/else is too linear to reason about, we can use a condition filter. 

```js
/** Micro state machine: uses functions to check conditions, rather than if/else branching. */
const msm = { 
	off: (e) => e === 0, 
	on: (e) => e === 1
};
```


Even more specifically, why isn't this packaged as code itself?

```JS
new MIStateMachine("a").pulse('to').variable('x').state(1);
new State(1).of('a')
```


This is where we run into the first issue: code is powerful becuase it is composable. This means source code is, by deafult, not precisely engineering. Where engineering focuses on first principles, problem-solving, constraint, design, structure (etc.), source focuses on what is useful now. It is closer to constructing schematics, composable vocabulary as scaffolding.

This means the engineer ends up constructing their own constraints, libraries, and extension vocabulary, from base grammar.
