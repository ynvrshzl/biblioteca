2, Schemata (Interactive Sourcecode IDE project) exploits the source-driven aspect of source-code, while affording graphical interactives at the GUI level. Inspired by brilliant.org's approach to interactive learning. This bases it's theory on the idea that "there are more or less optimal models of represatation for things." For example, typing easings onto a curve is trivial yet costly for cognitive simulation, while interactive input is intuitive and instanteous. If this is true at the level of a facade, only time will tell how this scales with interconnected complex systems.

3, If code favors source-over-representation, then perhaps the primary structure missing from Programming Languages today, is not representational or tooling; but lexical architecture, specifically, Categorization.. Tangible Domains of Separation. This offers a unique Symbiote: From the Engineer's perspective, categories afford organized retrieval and automaticity. From the reader's perspective, the code is organized and navigable. 

There are two central propositions for categorical areas in this case; Scientific and Constructive. Scientific category includes the Role-based responsibilities of units in code, e.g., `"Math"` and `"Networking"` While the Prototypal/ Construction aspect refers to the Engineering aspects of code, e.g., `"Program"` and `"Modules"`

Categories can be as simple as Object-trees, e.g., `"com.math.add(x, y)"` or as sophisticated as Language syntax can allow: e.g., `"a|c->d:e"` in the case of Grammatica, categories are a core part of it's design
